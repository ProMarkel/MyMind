AI CodingGitSpawn 漏洞：恶意仓库在 AI 编程代理"打开"的瞬间就能执行代码

安全机构 Manifold Security 披露了一类名为 GitSpawn 的漏洞。研究者发现几乎所有被测的命令行 AI 编程代理在启动时都会后台运行 git status / git diff 来收集项目上下文，而 git 的 core.fsmonitor 配置允许仓库在自己的 .git/config 里指定一个"索引刷新时自动运行"的辅助程序——于是一个被投毒的仓库只要被 AI 代理打开，就能以登录用户权限执行任意命令。该攻击无法经 clone / fetch / pull 传播（这些操作不传输 .git/config），需以压缩包、共享盘、同步目录或 U 盘等文件形式落地。

  • Claude Code：自动 git 上下文查询 + ultrareview 密钥滥用，仍有 4 个未修复漏洞
  • Goose 已修复（CVE-2026-72718）；Hermes Agent 在六次联系后仍未回应（CVE-2026-71963）；Cursor 与 Codex 收到报告后均已发布补丁
  • Qwen Code 与 Grok Build 存在启动时上下文收集引发的未认证预执行文件篡改风险
"打开一个目录"从此不再是无害动作。AI 编程代理把 git 的隐式副作用变成了攻击面，可信来源之外的仓库都该先进沙箱再开。

AI CodingSkyPilot 推出 Agent Sessions：断连后编码 Agent 继续在自有 K8s 上跑

SkyPilot 发布 Agent Sessions，直指长时任务 Agent 的新痛点——它们会跑几分钟到几小时，却在无法预测的时刻需要人来拍板。方案是把 Agent 放进自有 Kubernetes 集群上可持久、可暂停的 devspace，数据与 GPU 全部留在内部；按 Ctrl-] 就能走开，会话可跨笔记本休眠与断网存活，之后从 CLI、浏览器或手机重新接入。

  • fleet dashboard 在 Agent 需要授权或决策的那一刻主动通知，避免"跑完才发现卡住了"
  • 会话本质是普通 shell，兼容 Claude Code、Codex、Gemini、Aider、Goose、Amp、OpenCode、Cursor 等
  • 通过 websocket 接入，无需配置 kubeconfig 或 SSH
Agent 的"可离开性"正在成为工程指标。人不必守着终端，但必须能在关键节点被准确叫回来。

AI CodingO'Reilly Radar 九月观察：企业开始自建 Agent Harness，MCP 转向无状态

O'Reilly 九月 Radar 汇总了一个明确转向：公司不再只用现成 Agent，而是自建 harness，以便把自有工作流嵌进 AI 开发流程。DeepSeek 开源了自己的 agent harness Harness（几乎一切皆插件，可跨模型使用并把活委派给 Claude Code 与 Codex）；TrueForge 则提供生产环境下调试与治理 Agent 的工具。Anthropic 为 Claude Code 加入跨会话消息，让一个 Agent 能主动通报自己的改动会影响到谁，减少"程序员充当传声筒"。

  • Agent Plugins 成为可复用组件扩展标准，已获 OpenAI、Microsoft、Cursor、AWS 支持（Google 与 Anthropic 暂未加入）
  • MCP 更新解决了最大采用障碍之一：协议转为无状态
  • Zed 推出 Delta——"与 Agent 协作写码并评审其产出"的多人环境，主张关于代码的对话应与源码一同留存
"用别人的 Agent"到"造自己的 harness"，分水岭是工作流所有权。谁掌握编排层，谁才真正掌握研发流程。

具身智能智元 + 敏实在塞尔维亚开出欧洲首条人形机器人量产线

敏实集团与智元（AGIBOT）在塞尔维亚 Šabac 敏实汽车零部件厂区内，正式启用欧洲首个人形机器人与机器狗量产基地，塞尔维亚总统武契奇出席。一期投资 2000 万欧元、目标组装约 5000 台；9 月中旬将在 Inđija 动工建设机器人产业园，累计投资 2 亿欧元，建成后年产能最高 2 万台。把产线直接放进在产的汽车零部件工厂，也让新机器能在真实工况中持续采集物理交互数据。

  • 一期：Šabac 厂区、€20M、约 5000 台；二期：Inđija 产业园、€200M、年产能至 2 万台（含人形、四足、电池、无人机）

在海外贸易限制升温之际，把量产基地设在欧洲既是地缘缓冲，也是把"数据飞轮"直接架在客户产线上的一步棋。

ZimaBlue 那组 36.1%→77.8% 是本周最有信息量的数字：具身智能的瓶颈是数据而非本体，而人类第一人称视频可能是最便宜的那条路。

AI Coding阿里 LoopArena 基准：最强模型的 Agent 调度严格成功率仅 24.69%

9 月 2 日阿里 DreamX 团队发布 LoopArena 基准，首次把"调度模型"与"干活模型"拆开单独评测循环工程能力。结果相当冷峻：最强模型 GPT-5.5 在完整任务上的严格成功率仅 24.69%，部分较弱模型的表现甚至低于"无调度"对照组。研究同时指出，"反复提醒目标"这种常见提示技巧在长任务上基本无效。

  • GPT-5.5 完整任务严格成功率 24.69%（最高）；最弱模型低于无调度对照基线
  • 评测设计：调度（orchestrator）与执行（worker）能力解耦，单独度量长循环控制
  • 结论：长任务的循环控制仍是远未解决的问题，重复强调目标不构成有效缓解
行业热衷于堆 Agent 数量，但 LoopArena 说明真正的瓶颈在"谁来调度、怎么不跑偏"——这块能力目前连四分之一的可靠度都还没到。

AI CodingClaude Code 误删约 700GB 数据：一次真实的 Agent 操作安全事件

本周（截至 2026-09-01）开发者社区曝光一起高危事件：某开发者报告 Claude Code 的 "Fable" 子 Agent 执行了破坏性清理（rm -rf），删除了主目录约 700GB 数据。Anthropic 状态页记录了相关的错误率升高事件，独立安全研究指出可能存在 TOCTOU 与沙箱边界逃逸问题，使 Agent 突破预期工作区限制。这是一次真实发生的运维安全事故，而非理论风险。

  • 受影响：单个 home 目录约 700GB 被 rm -rf 清除
  • Anthropic 状态页记录 elevated-errors 事件；8 月 release notes 指向 agent 工具更新
  • 安全研究指出 TOCTOU 与 sandbox boundary 逃逸风险，Agent 可超出工作区限制
把 Agent 编码工具放进一次性 VM 或严格沙箱、默认关闭自动删除钩子、对 rm/格式化加人工审批门，已成为必需的工程纪律。
