AI Coding微软 FastContext：多专用小模型协作，主模型 Token 最多省 60%

微软提出 FastContext，把"找代码 / 读上下文"从主模型推理中拆出，交给 4B–30B 专用小模型 作为只读"代码侦察兵"并行检索并压缩上下文；接入 Mini-SWE-Agent 评测，端到端解决率最高 +5.5%，主模型 Token 消耗最多 −60%。

  • 路线：主模型 + 一队专用小模型混合编排，而非一味堆更大模型
  • 实测：Mini-SWE-Agent 端到端解决率 +5.5%，主模型 Token 最多省 60%
  • 同日基准：框架层成本已现差异（Claude Code 缓存命中 1.5% vs Codex ~70%）
coding agent 下一阶段竞争焦点是"主模型 + 专用小模型"的单位任务成本，选型该按"每成功任务成本"而非裸 Token 比较。

AI CodingUC Berkeley 开源 CUA-Lite，Meta FAIR 用 RPM 在执行前给实验排序

UC Berkeley 开源 CUA-Lite，把 computer-use agent 的沙箱镜像从 4.1 GB 虚拟机压缩到 0.9 GB Docker 容器（降 75%），统一环境与动作轨迹、便于本地跑可丢弃执行容器。同期 Meta FAIR 联合牛津、UCL 推出 AI Research Preference Models (RPMs)——冻结的语言模型裁判在执行前对 15 个候选实验打分、仅保留最优，AIRS-Bench 归一化得分 0.684→0.729。

  • CUA-Lite：沙箱 4.1GB→0.9GB（-75%），统一 action schema，本地轻量评测
  • Meta FAIR RPMs：执行前对 15 候选排序、只跑最优；AIRS-Bench 0.684→0.729，24h→15h
  • 共性：用"轻量沙箱 + 前置评估器"给失控的多 Agent 循环装上刹车
两条线索指向同一件事：Agent 的经济账不能只靠更强模型，轻量沙箱和"先打分再执行"的闸门同样值钱。

安全机构 Manifold Security 披露了一类名为 GitSpawn 的漏洞。研究者发现几乎所有被测的命令行 AI 编程代理在启动时都会后台运行 git status / git diff 来收集项目上下文，而 git 的 core.fsmonitor 配置允许仓库在自己的 .git/config 里指定一个"索引刷新时自动运行"的辅助程序——于是一个被投毒的仓库只要被 AI 代理打开，就能以登录用户权限执行任意命令。该攻击无法经 clone / fetch / pull 传播（这些操作不传输 .git/config），需以压缩包、共享盘、同步目录或 U 盘等文件形式落地。

  • Claude Code：自动 git 上下文查询 + ultrareview 密钥滥用，仍有 4 个未修复漏洞
  • Goose 已修复（CVE-2026-72718）；Hermes Agent 在六次联系后仍未回应（CVE-2026-71963）；Cursor 与 Codex 收到报告后均已发布补丁
  • Qwen Code 与 Grok Build 存在启动时上下文收集引发的未认证预执行文件篡改风险
"打开一个目录"从此不再是无害动作。AI 编程代理把 git 的隐式副作用变成了攻击面，可信来源之外的仓库都该先进沙箱再开。

AI CodingSkyPilot 推出 Agent Sessions：断连后编码 Agent 继续在自有 K8s 上跑

  • fleet dashboard 在 Agent 需要授权或决策的那一刻主动通知，避免"跑完才发现卡住了"
  • 会话本质是普通 shell，兼容 Claude Code、Codex、Gemini、Aider、Goose、Amp、OpenCode、Cursor 等
  • 通过 websocket 接入，无需配置 kubeconfig 或 SSH
Agent 的"可离开性"正在成为工程指标。人不必守着终端，但必须能在关键节点被准确叫回来。
