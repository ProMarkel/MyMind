AI CodingOpenAI 启动"28 天 Codex 承诺"，Day 1 默认提速约 50%

OpenAI Codex 负责人 Tibo 立下 Flag：未来连续 28 天每天给 Codex / Work 用户带来一项明确改进，否则当天直接重置用量。Day 1（10/5 生效）把 GPT-6 Astra 与 GPT-6.1 Sol 的默认输出速度从约 30 token/s 提到 50，纯属基础设施优化、不涉及模型改动，约两小时内覆盖全产品及 OpenCode / Pi / Amp / Devin 等第三方 harness。

  • 提速来自服务端请求处理优化，无需用户改任何设置
  • Partner 工具（OpenCode / Pi / Amp / Devin）同步受益，强化 ChatGPT 登录生态的平台黏性
  • 承诺：28 天内无改进的日子直接做完整用量重置
"每天一个改进"把 agent 的真实痛点（长循环里的等待时间）摆上台面——对要读文件、跑测试、反复迭代的 coding agent，每步省下的延迟会沿数百次往返叠加成真实吞吐。

AI CodingOpenAI 推 textGrain 隐形水印，Auto-review 免费开放

为响应 EU AI Act，OpenAI 开放 textGrain 隐形文本水印（生成时按词选择埋入统计信号、默认关闭，EU 区 ChatGPT/Codex 后续将默认携带），并计划开源检测技术。同期 Auto-review（即"Approve for me"）对全部 ChatGPT 登录用户免费开放——再引入第二个 agent 专盯主 agent 的高风险操作与偏离意图动作。

  • 水印在 1% 误报率下，400 token 文本检出率约 95%；改写 25% 词汇后检出率跌到 17%
  • Auto-review 不是"免费"二字：长任务里手动点批准本身成负担，完全放开又风险高，第二个 agent 是折中
  • ChatGPT 周活已达 12 亿人；本月将在美国测试图片广告位（明确标注、与答案分离）
当 agent 进入以"小时计"的真实任务，权限管理不能再靠人逐步点确认——"用 agent 管 agent"正从技巧变成基础设施。

AI CodingGitHub 重构核心 Git 基础设施，面向"agent 规模"并发提交

传统版本控制引擎在数千个自治 coding agent 同时提交时会遭遇严重锁竞争。GitHub 正重建核心存储与传输层，优先并行吞吐、降延迟、支撑海量自动化集成流水线，以消化 agent 舰队每天生成的成千上万 PR 与提交爆发。

  • 目标：非阻塞的并发 tree 更新，避免 commit lock 成为 CI/CD 瓶颈
  • 受众：运行连续 agentic loop 的 AI-first 研发组织与平台工程团队
  • 代价：下游 legacy CI/CD runner 需升级以消化非阻塞并发更新
开发者工具正从"给人用"转向"给高频智能体用"——当 agent 把提交量放大几个数量级，连 Git 这种底层基础设施都被迫抛弃锁重范式，这是 agent 规模化的真实代价。
